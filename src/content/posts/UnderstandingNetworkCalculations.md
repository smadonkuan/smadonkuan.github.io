在網路工程中，「計算」不只是數學運算，而是一種用來理解、設計與驗證網路結構的基本能力。

本文從資料單位、傳輸速率，一路推進到 IP 與子網路的規劃，並延伸到 VLSM 與 IPv6，建立一套完整的網路計算觀念架構。

---

## 一、資料單位與位元結構

### 1. Bit 與 Byte 的本質差異

**Bit（b）**：最小資訊單位，只能表示 0 或 1

**Byte（B）**：由 8 個 bit 組成，是儲存與傳輸的基本單位

**特別注意：**
- 網路頻寬使用 **bit** 為單位（bps）
- 儲存容量使用 **Byte** 為單位（B）
- **兩者相差 8 倍**

### 2. 常見單位換算

注意：有兩種標準，需區分使用情境

**二進位制（KiB, MiB, GiB）**：1024 為基底（作業系統、記憶體）

**十進位制（KB, MB, GB）**：1000 為基底（網路傳輸、硬碟標示）

| 單位 | 二進位換算 | 十進位換算 |
|------|-----------|-----------|
| 1 KB | 1024 B | 1000 B |
| 1 MB | 1024 KB | 1000 KB |
| 1 GB | 1024 MB | 1000 MB |
| 1 TB | 1024 GB | 1000 GB |

**實務建議：**
- **網路計算時通常使用十進位**（因為 ISP 和網路設備都這樣標示）
- 檔案系統顯示時使用二進位（這就是為什麼 1TB 硬碟在電腦上顯示不到 1TB）

## 二、傳輸速率與時間的計算邏輯

### 核心公式

```
傳送時間 = 資料量 ÷ 傳輸速率
```

**重要提醒：**
- 資料量需以 **bit** 表示
- 傳輸速率需以 **bps** 表示

### 範例計算

**情境：**
- 檔案大小 = 80 MB
- 頻寬 = 10 Mbps

**方法一（網路常用，十進位）：**
```
80 MB = 80 × 8 = 640 Mb
傳送時間 = 640 Mb ÷ 10 Mbps = 64 秒
```

**方法二（嚴格二進位）：**
```
80 MB = 80 × 1024 × 1024 × 8 bit = 671,088,640 bit
      = 671.09 Mb
傳送時間 = 671.09 Mb ÷ 10 Mbps ≈ 67.1 秒
```

**常見錯誤：**
- ❌ 忽略 Byte 與 bit 的轉換（相差 8 倍）
- ❌ 混用 MB 與 Mb
- ❌ 直接用 80 ÷ 10 = 8 秒（忘記轉換單位）

### 快速換算技巧

**頻寬轉檔案速度：**
```
100 Mbps ÷ 8 = 12.5 MB/s（理論值）
1 Gbps ÷ 8 = 125 MB/s（理論值）
```

## 三、頻寬與實際效能的差異

### 理論頻寬 ≠ 實際速度

影響因素包括：
1. **封包標頭與協定開銷**（Overhead）
2. **重傳與錯誤修正**
3. **多使用者共享頻寬**
4. **路由延遲與繞路**

### 協定開銷實例

傳送 1500 byte 的資料（標準 MTU 大小）：

| 項目 | 大小 |
|------|------|
| 實際資料 | 1500 bytes |
| TCP 標頭 | 20 bytes |
| IP 標頭 | 20 bytes |
| Ethernet 標頭 + CRC | 18 bytes |
| Interframe Gap | 12 bytes |
| **總共需傳送** | **1570 bytes** |

**實際效率 = 1500 ÷ 1570 ≈ 95.5%**

### 近似公式

```
實際可用速度 ≈ 理論頻寬 × 85% ~ 95%
```

**不同情境的效率：**
- TCP over Ethernet：85-95%
- 高延遲網路（如衛星）：60-80%
- 擁塞網路：可能低於 50%

## 四、IP 位址與遮罩的結構本質

### IPv4 結構

**IPv4 位址長度：32 bit**

**範例：192.168.1.0**

十進位表示：`192.168.1.0`

二進位表示：`11000000.10101000.00000001.00000000`

### 子網路遮罩（Subnet Mask）

用來區分「網路位址」與「主機位址」

**CIDR 表示法：**
- `/24` → 前 24 bit 為網路部分，後 8 bit 為主機部分
- `/26` → 前 26 bit 為網路部分，後 6 bit 為主機部分
- `/30` → 前 30 bit 為網路部分，後 2 bit 為主機部分

**對應的遮罩值：**

| CIDR | 遮罩 | 網路位元 | 主機位元 |
|------|------|---------|---------|
| /24 | 255.255.255.0 | 24 | 8 |
| /25 | 255.255.255.128 | 25 | 7 |
| /26 | 255.255.255.192 | 26 | 6 |
| /27 | 255.255.255.224 | 27 | 5 |
| /28 | 255.255.255.240 | 28 | 4 |
| /29 | 255.255.255.248 | 29 | 3 |
| /30 | 255.255.255.252 | 30 | 2 |

## 五、可用主機數的計算原理

### 基本公式

```
可用主機數 = 2^n - 2
```

**其中：** n = 主機位元數

**減 2 的原因：**
- 全 0 → 網路位址（Network Address）
- 全 1 → 廣播位址（Broadcast Address）

### 計算範例

**範例 1：/24 網段**
```
主機位元 = 32 - 24 = 8
可用主機數 = 2^8 - 2 = 256 - 2 = 254
```

**範例 2：/26 網段**
```
主機位元 = 32 - 26 = 6
可用主機數 = 2^6 - 2 = 64 - 2 = 62
```

**範例 3：/30 網段**
```
主機位元 = 32 - 30 = 2
可用主機數 = 2^2 - 2 = 4 - 2 = 2
```

### 常用網段快速參考表

| CIDR | 主機位元 | 總 IP 數 | 可用主機數 | 常見用途 |
|------|---------|---------|-----------|---------|
| /24 | 8 | 256 | 254 | 小型辦公室網路 |
| /25 | 7 | 128 | 126 | 中型部門 |
| /26 | 6 | 64 | 62 | 小型部門 |
| /27 | 5 | 32 | 30 | 小組網路 |
| /28 | 4 | 16 | 14 | 小型設備群組 |
| /29 | 3 | 8 | 6 | 極小型網路 |
| /30 | 2 | 4 | 2 | 點對點連線 |
| /31 | 1 | 2 | 2* | 點對點連線（RFC 3021） |

**補充：RFC 3021**

/31 可用於點對點連線，不需減 2，因為在點對點網路中不需要網路位址和廣播位址。

## 六、子網切割的設計邏輯

### 切割目的

1. **提高 IP 使用效率**：避免位址浪費
2. **分隔廣播域**：減少網路流量
3. **強化管理與安全性**：邏輯隔離不同部門

### 借用位元的效果

**以 /24 (Class C) 為例：**

| 借用主機位元數 | 新遮罩 | 子網數量 | 每子網可用主機 |
|--------------|--------|---------|---------------|
| 1 bit | /25 | 2 | 126 |
| 2 bit | /26 | 4 | 62 |
| 3 bit | /27 | 8 | 30 |
| 4 bit | /28 | 16 | 14 |
| 5 bit | /29 | 32 | 6 |
| 6 bit | /30 | 64 | 2 |

### 子網切割範例

**情境：**
- 原始網段：192.168.1.0/24
- 需求：切成 4 個子網

**計算：**
```
需要 4 個子網 → 需要借 2 個 bit（2^2 = 4）
原本 /24 → 借 2 bit → 新遮罩 /26
```

**結果：**

| 子網 | 網路位址 | 可用範圍 | 廣播位址 |
|------|---------|---------|---------|
| 1 | 192.168.1.0 | 192.168.1.1 - 192.168.1.62 | 192.168.1.63 |
| 2 | 192.168.1.64 | 192.168.1.65 - 192.168.1.126 | 192.168.1.127 |
| 3 | 192.168.1.128 | 192.168.1.129 - 192.168.1.190 | 192.168.1.191 |
| 4 | 192.168.1.192 | 192.168.1.193 - 192.168.1.254 | 192.168.1.255 |

### 設計時的平衡考量

需要在以下三者之間取得平衡：
- 子網數量
- 每子網主機數
- 管理複雜度

## 七、進階觀念補充

### 1. VLSM（Variable Length Subnet Mask，可變長度子網路遮罩）

**核心概念：** 可依實際需求分配不同大小的子網

**傳統子網切割的問題：**
- 所有子網大小相同
- 容易造成 IP 位址浪費

**VLSM 的優勢：**
- 彈性分配
- 最大化 IP 使用效率

**實例：**

假設公司有以下需求：
- 部門 A：需要 100 台設備
- 部門 B：需要 50 台設備
- 部門 C：需要 20 台設備
- 3 條點對點連線：各需要 2 個 IP

**VLSM 規劃：**

| 部門 | 需求 | 配置網段 | 遮罩 | 可用主機 |
|------|------|---------|------|---------|
| 部門 A | 100 | 192.168.1.0/25 | /25 | 126 |
| 部門 B | 50 | 192.168.1.128/26 | /26 | 62 |
| 部門 C | 20 | 192.168.1.192/27 | /27 | 30 |
| 連線 1 | 2 | 192.168.1.224/30 | /30 | 2 |
| 連線 2 | 2 | 192.168.1.228/30 | /30 | 2 |
| 連線 3 | 2 | 192.168.1.232/30 | /30 | 2 |

**VLSM 規劃原則：**
1. 先分配需求最大的
2. 由大到小依序分配
3. 避免位址重疊

### 2. CIDR 與路由聚合（Route Aggregation）

**CIDR 不僅用於子網劃分，也能縮減路由表大小**

**聚合範例：**

原本有 4 個獨立的 /24 網段：
```
192.168.0.0/24
192.168.1.0/24
192.168.2.0/24
192.168.3.0/24
```

可以聚合為一個 /22：
```
192.168.0.0/22
```

**驗證聚合的正確性：**
```
192.168.0.0   = 11000000.10101000.00000000.00000000
192.168.3.255 = 11000000.10101000.00000011.11111111
                                  ^^^^^^
                                  前 22 bit 相同
因此可聚合為 /22
```

**聚合的好處：**
- 減少路由表項目
- 降低路由器負擔
- 加快路由查找速度

**聚合的限制：**
- 必須是連續的網段
- 必須從 2 的次方邊界開始

### 3. IPv6 簡介

**基本特性：**
- 位址長度：**128 bit**（IPv4 是 32 bit）
- 表示方式：8 組 16 進位，用冒號分隔
- 範例：`2001:0db8:85a3:0000:0000:8a2e:0370:7334`

**常見簡化規則：**
1. 每組前導零可省略：`0db8` → `db8`
2. 連續的零可用 `::` 取代一次：`2001:0db8:0000:0000:0000:0000:0000:0001` → `2001:db8::1`

**常見子網配置：**

| 用途 | 典型前綴 | 說明 |
|------|---------|------|
| ISP 分配給客戶 | /48 | 可切出 65,536 個 /64 子網 |
| 企業內部使用 | /56 | 可切出 256 個 /64 子網 |
| 單一網段 | /64 | **最常見配置** |
| 點對點連線 | /127 | 類似 IPv4 的 /31 |

**為什麼 /64 最常見？**

1. **SLAAC 自動配置需要**：IPv6 的無狀態位址自動配置（SLAAC）使用 EUI-64 格式，需要 64 bit 的主機部分
2. **足夠的位址空間**：2^64 ≈ 1800 京個位址，永遠用不完
3. **簡化管理**：統一使用 /64，不需計算子網大小

**IPv6 子網設計重點：**
- 不再擔心位址不足
- 著重於**管理清晰度**與**安全性**
- 通常按照組織架構或功能劃分

## 八、網路計算的真正意義

計算網路不是為了套公式，而是在回答三個核心問題：

### 1. 系統需要支援多少設備？
- 評估目前與未來 3-5 年的成長
- 預留適當的擴充空間（通常保留 20-30%）

### 2. 是否需要進行區域分割與隔離？
- 不同部門是否需要邏輯隔離？
- 是否有安全性考量（DMZ、內網、管理網路）？
- 如何控制廣播域大小？

### 3. 如何在效率與管理成本之間取得平衡？
- 過大的網段：IP 充足但管理困難、廣播風暴風險
- 過小的網段：管理清晰但 IP 可能不足、路由表膨脹

**這正是網路設計的工程思維。**

## 九、實務案例分析

### 案例 1：中小企業網路規劃

**需求：**
- 員工數：150 人
- 部門：業務、工程、行政、訪客
- 設備：電腦、IP 電話、印表機、無線 AP

**分析：**
```
業務部：50 人 × 1.5 倍（電腦+電話）≈ 75 台
工程部：30 人 × 2 倍（多台設備）≈ 60 台
行政部：20 人 × 1.5 倍 ≈ 30 台
訪客網路：預留 30 台
基礎設施：印表機、伺服器、AP 等 ≈ 20 台
```

**建議方案：**

| 網段 | CIDR | 可用主機 | 用途 |
|------|------|---------|------|
| 192.168.10.0/25 | /25 | 126 | 業務部 |
| 192.168.10.128/26 | /26 | 62 | 工程部 |
| 192.168.11.0/26 | /26 | 62 | 行政部 |
| 192.168.11.64/26 | /26 | 62 | 訪客網路（隔離） |
| 192.168.11.128/27 | /27 | 30 | 基礎設施 |

### 案例 2：資料中心點對點連線

**需求：**
- 10 對伺服器之間的直連網路

**方案：**
- 使用 /30 或 /31
- /30：每條連線 4 個 IP，可用 2 個
- /31：每條連線 2 個 IP，可用 2 個（RFC 3021）

**推薦：** 使用 /31 節省位址空間

## 十、常見錯誤與陷阱

### ❌ 錯誤 1：單位轉換錯誤
```
錯誤：10 Mbps = 10 MB/s
正確：10 Mbps = 10 ÷ 8 = 1.25 MB/s
```

### ❌ 錯誤 2：忘記扣除網路位址和廣播位址
```
錯誤：/24 有 256 個可用 IP
正確：/24 有 254 個可用 IP（256 - 2）
```

### ❌ 錯誤 3：過度切割子網
```
問題：10 台設備卻配置 /28（14 個可用 IP）
風險：未來擴充困難
建議：預留成長空間，使用 /26 或 /27
```

### ❌ 錯誤 4：過大的網段
```
問題：50 台設備卻配置 /16（65,534 個可用 IP）
風險：
- 廣播域過大，影響效能
- 管理困難
- 安全性問題
```

### ❌ 錯誤 5：VLSM 分配順序錯誤
```
錯誤：先分配小網段，再分配大網段
結果：位址空間碎片化，大網段無連續空間

正確：
1. 先分配需求最大的
2. 由大到小依序分配
